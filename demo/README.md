# 多智能体协作修复代码：入门演示

## 可视化交互界面（推荐）

在项目根目录运行 `node demo/server.mjs`，然后打开 http://127.0.0.1:4321 。也可以双击 `demo/start-visual-demo.cmd` 启动服务。保持启动窗口打开，关闭窗口即停止服务。

- **开始演示**：自动逐步推进真实执行的修复流程。
- **单步执行**：每点一次推进一个阶段，便于检查交接和代码变化。
- **暂停播放 / 继续演示**：随时停下来阅读。
- **修复预算**：选择两轮观察成功，或一轮观察预算耗尽后的失败停止。
- **代码版本**：切换原始代码和当前修复代码。
- **导出交接记录**：保存本次运行的 JSON 数据。

每次演示都在 `demo/runs/visual-*` 新建独立工作目录，真实写入并测试固定示例代码。最近测试属于旧轮次时，界面会明确显示“上轮结果”。重新开始会保留旧运行文件；刷新页面会恢复服务内最近一次任务并暂停播放。角色决策仍是离线预设策略，不调用大模型。

这是一个可运行的离线教学 Demo，演示规划员、编程员、测试员通过结构化消息协作，修复待办任务添加功能。角色决策是预设规则，不是真实大模型推理；代码修改、子进程测试、失败反馈和运行记录真实执行。

## 运行

需要 Node.js 22 或更新版本，无需安装依赖、配置密钥或联网。在项目根目录执行：

```powershell
node demo/demo.mjs
```

然后双击 `demo/latest-report.html`。报告是静态结果，重新运行上述命令会更新它。每次运行还会生成独立的 `demo/runs/run-*` 目录，包含修复代码 `todo.mjs`、测试程序 `verify.mjs`、完整消息 `trace.json` 和该次报告 `report.html`。

## 你会看到什么

1. 原始代码不检查输入，四个验收项只通过一个。
2. 规划员输出任务编号、四条验收条件和最多两轮修复的限制。
3. 编程员第一轮只拒绝空字符串，通过两个验收项。
4. 测试员真实执行测试，发现纯空白未拒绝、首尾空白未去除。
5. 编程员第二轮根据这两项反馈使用 `trim()`，四项全部通过。
6. 调度程序确认测试结果，交付最终代码与过程记录。

这是一条固定示范路径，不是衡量多智能体优于单智能体的实验。测试仅覆盖示例规定的字符串输入；没有声称代码在所有输入下正确。

## 读源码的顺序

- `planner()`：需求如何变成结构化任务。
- `coder()`：角色如何接收计划与上一轮反馈。
- `tester()`：外部执行器怎样返回可检查的实际结果。
- `main()`：调度程序怎样推动循环、保存状态并停止。
- `report()`：把过程变成便于阅读的中文报告。

## 如何进一步接入真实模型

保留调度程序、测试器与消息字段，把 `planner()` 和 `coder()` 中的固定结果替换为模型响应。项目原有 `lab.mjs` 已包含真实模型调用实现，可作为接入参考。本演示本身不读取密钥，不会产生模型费用。

真实模式需要额外处理：校验模型输出字段、限制改动文件范围、设置调用超时与费用预算，并将生成代码放入受限执行环境。这里的测试器只用于仓库内随附的固定示例，不应直接拿来执行不可信模型或用户生成的任意代码。

为了比较协作收益，还应增加同模型、同工具、相近预算的单智能体版本，并在独立任务集上比较成功率、成本与耗时。
