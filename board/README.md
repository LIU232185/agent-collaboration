# 协作任务看板

## 协作方式如何选择

- “关键词规则”：包含“对比、比较、选择、争议、优缺点”时选择 debate；否则含“调研、收集、探索”时选 parallel；其余为 chain。有多个关键词时比较类优先。这一步不调用模型。
- “DeepSeek 选择”：仅在 DeepSeek 配置可用时启用，自动切换真实后端。先调用模型输出 mode 与简短 reason，严格校验后再构建固定拓扑。失败会停止，不静默回退关键词规则。最多 1 次选择 + 4 次角色调用；选择理由和决策记录可在交接时间线查看。
- 手动选择：直接使用你选择的协作方式。

chain 逐步交接；parallel 两个角色先独立展开；debate 使用相同汇合拓扑，但要求研究员给主要方案、实践员给替代方案和反例，再审查汇总。目前不是多轮辩论。以上均未训练路由器，角色仍固定、各节点仍调用同一模型；只实现协作方式选择这一层，不等于完整 MasRouter。

## DeepSeek Flash 接入

适配官方 `https://api.deepseek.com/chat/completions`，默认模型 ID `deepseek-flash`，关闭思考模式，每次最多 3000 输出 token。按 2026-10-20 的[官方文档](https://api-docs.deepseek.com/zh-cn/)，原 `deepseek-v4-flash` 已下线，旧别名会由新版 Flash 服务；如使用第三方平台，应按该平台文档填写其实际模型 ID 与 HTTPS base URL。

项目已提供 `.env.deepseek.example`。在根目录 `.env` 本地填写 `DEEPSEEK_API_KEY`，保持 `LLM_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`。密钥不发到聊天、不提交 Git。

看板点击“重新读取本地 API 配置”后，选择真实模型并提交任务。读取配置不调用模型，也不验证密钥有效性；界面确认后运行任务才产生模型调用。开始真实任务前关闭“故障与恢复实验”（该算术案例仍为零模型调用的规则实验）。原有 OpenAI Responses 模式可用 `LLM_PROVIDER=openai` 与原 `OPENAI_*` 配置启用。

新增“故障与恢复实验”：勾选后配置采购算术题、金额篡改或依据遗漏、Challenger / Inspector 防护和重算预算。观察异常消息隔离、退回重算、验证放行或预算耗尽阻断；同题四组实际运行的结果与消息版本随记录导出。详见 [论文方法与本地边界](../reproductions/mas-resilience/README.md)。这部分不调用模型，不能代表论文 LLM 恢复率。

输入问题，观察规则路由选择、智能体状态、实际交接和最终输出。独立入口，不影响原工作台。

在项目根目录运行 `npm run board`，打开 http://127.0.0.1:4322 。需要 Node.js 22+，无需安装新依赖。默认零 API 费用。

- 支持自动规则选择、链式协作、并行探索、多视角讨论。
- 点击节点查看职责、收到的材料与交付内容；点击事件查看对应的交接快照。
- 本地记录保存在 `data/board-runs`；刷新恢复记录，服务重启后的未完成任务标为中断，不自动重试。
- 停止任务后不再启动新节点；已发出的真实模型请求仍可能执行和计费。
- 真实模式使用项目根目录 `.env` 中所选提供方的配置，支持 DeepSeek Chat Completions 与原有 OpenAI Responses。通过“重新读取本地 API 配置”启用。由用户在界面勾选费用确认并提交才调用模型；最多 4 次调用，每次最多 3000 输出 token。
- 真实节点复用现有研究员、实践员、审查员，汇总节点复用研究员身份。加载各自可共享 skills、memory，不加载私有 knowledge。

本地演示支持任意问题作为输入，但输出是清楚标注的通用规则模板，用来验证交接流程，不声称已解决该问题。真实模式才调用大模型生成针对问题的答复。该看板尚未接入训练后的 MasRouter，自动路由为关键词规则；并行探索和多视角讨论使用相同的汇合拓扑。当前没有逐 token 流式输出、模型用量核算、工具执行或独立事实验证；耗时是本地墙钟时间，演示等待仅用于呈现节点变化。

验证：`node --test board/engine.test.mjs`。测试覆盖三种流程、交接来源、并行状态、失败停止、取消与注入式模型适配器，不调用付费模型。
