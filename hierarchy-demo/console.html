MAS-Resilience · ICML 2025

执行者在汇总子任务时质疑输入（Challenger）；独立 Inspector 在每个团队输出和最终交付进入下游前检查。实质错误隔离 → 原角色最多修订两次 → 独立复审。非阻断意见保留为建议；仍错误的团队消息被隔离，其他团队可交付带限制的结果；最终候选仍不合格时明确要求人工复核。

子任务由团队负责人质疑，团队级消息才经过独立 Inspector。审查也是模型判断，不能保证正确。没有声称复现论文数据集成绩或故障鲁棒性指标。

YOUR TEAM / ARCHITECTURE MAPPING

与你们的三个顶层 Agent 怎么对应？

当前入口已按此名册固定三个顶层团队及六个子 Agent。它们通过独立职责提示真实调用 DeepSeek；尚未连接你们另一个平台上已有 Agent 的接口、知识库和业务工具。校招生问题不等于摇摆户问题：需求团队仅作事实澄清，营销团队仅作业务价值与方案设计，必须说明适用边界。

摇摆户 Agent

顶层：整合客户判断

子 Agent：需求与事实核查子 Agent：行为与障碍分析

营销 Agent

顶层：整合方案并处理反馈

子 Agent：方案设计子 Agent：效果评估

风控 Agent

顶层：整合风险约束

子 Agent：权限与边界子 Agent：证据与承诺检查

团队内：子任务 → 顶层汇总与质疑。团队间：顶层消息 → 独立 Inspector → 依赖该消息的其他顶层团队。

顶层 Agent 同样可以编排、交接、审查和退回修订。本次已停止生成新顶层角色。三个团队均参与，协作方式决定先后、共享消息和是否进行额外交叉质疑。新增场景可以配置新团队注册表，但不能让一次路由调用擅自创建身份。

当前恢复 ≠ 跨任务自进化

当前运行发现实质错误后，可退回原角色最多修订两次，每次均复审；这只改变本次消息。当前通用入口没有将经验自动写入下一次策略，没有更新模型权重。

旧业务原型保留了提示策略提案与小规模留出对照，但未接入当前通用入口，也不足以证明业务提升。真正闭环需要：失败归因 → 候选提示/路由/记忆补丁 → 独立业务样例对照评测 → 达标后发布 → 持续监测与回滚。

路由与多场景训练：当前能做什么？

方案当前状态适用边界
手动指定方式可运行对照不同协作结构的基础入口
规则基线可运行便宜且可审计，但规则是人工写的，不保证最优
LLM 路由可运行，默认灵活，但每次需推理；只能选择候选方式，不能修改角色名册
原版 MasRouter 训练路由未接入有官方控制器合成计算验证，尚无经评测的业务路由权重

MasRouter 官方训练代码包含基于解题效果与推理成本的策略梯度项，同时有任务与表示学习损失。训练的是路由控制器，不等于必须微调每个业务大模型。

多场景需要：任务与团队能力描述、候选协作方式、统一成本记录、各场景独立效果评估，以及按场景留出的泛化测试。只训练当前三个业务团队，不能据此宣称可路由所有新场景。

LLM 路由并不是因为无法训练才使用的错误替代。先保留人工/规则/LLM 基线，收集对照结果；数据足够后可比较监督学习、上下文多臂老虎机与强化学习。单次选图且结尾才评分的问题未必需要复杂序列强化学习；动态多轮调度才更接近序列决策。不得直接用“审查通过”作为真实业务收益。

读取网络路径中

自动读取环境代理或已启用的 Windows 系统代理；关闭代理时走系统网络，支持 VPN TUN。始终校验证书。本机页面绕过代理；请求失败不会自动切换线路或付费重试。
