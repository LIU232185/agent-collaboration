这个 demo 如何理解？

摇摆户暂指“有意向但尚未决定的客户”。角色、客户和产品均为虚构示例，可按你们的实际定义替换。

真实执行：规则调度、消息交接、检查、重试与策略切换。模拟内容：客户分析、话术和业务判断。没有调用 LLM、更新模型参数或联系客户。

这里“进化”的是什么？
变化的是跨团队流程与生成约束。模型权重、子 agent 能力没有变化。策略和最近已完成记录仅保存在本浏览器；失败或无法保存时会明确提示。固定用例通过只说明本例没有回归，不能说明真实业务能力提升。


顶层 agent，我们能做什么？
顶层是团队对外的业务接口。这里营销不需要知道摇摆户内部如何分析，只接收统一摘要；风控不直接接管营销，只返回检查意见。调度器维护交接和预算。
同一套消息、检查、重试机制可以作用于顶层和子层。当前主流程固定，并没有训练一个能自动决定任意业务拓扑的路由器。
子 agent 在做什么？
子 agent 完成更细的分工，例如画像、犹豫分析、方案生成、授权核对。顶层封装本团队的工作，再把结果交给其他团队。本例的子步骤由程序编排，没有自主私聊。
恢复与进化怎么区别？
恢复：同一个任务里，风控发现问题，退回营销修订 v2 消息。
进化：跨任务改变策略，下一次先检查并约束生成。消息 v2 与策略 v2 是不同概念：前者是一份方案的新版本，后者是以后执行的方法。
与现有论文 demo 的关系
承接原看板的流程调度、交接追踪与故障恢复思路，增加明确的父子角色、跨团队反馈和可验证的策略切换。没有接入训练后的 MasRouter，也不是论文指标复现。
接入真实系统时，保留这些接口，把规则生成函数替换为各团队的模型或工具调用，并为业务效果建立独立评测数据。
建议按这个顺序体验
  1. 默认案例点“下一步”，看完客户团队内部三个子步骤。
  2. 选择“只看顶层”，定位摇摆户 → 营销 → 风控，以及退回修改。
  3. 运行有 / 无防护对照：观察不合格交付是否被挡住。
  4. 到策略进化页生成、验证并启用 v2，比较下一次是否还需要返工。
  5. 选择无授权案例：应该阻断；阻断不是交付成功，也不是系统故障。
