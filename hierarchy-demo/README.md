# 论文启发的真实 DeepSeek 协作看板

运行 `npm run hierarchy`（或 `node hierarchy-demo/server.mjs`），打开 http://127.0.0.1:4323/ 。直接输入问题，默认由 LLM 选择协作方式；也可以手动选择或使用可审计规则基线。根目录 .env 配置 DeepSeek 密钥；密钥不会返回浏览器。执行、审查、修订均为真实 API 调用，会产生费用，不提供假答案回退。

## 固定团队与协作方式

顶层注册表固定为摇摆户 Agent、营销 Agent、风控 Agent，每队两个固定分析子角色。LLM 可以分配任务，但不能创建组织人才专家等新身份。这些子角色是演示职责划分，并非已接入业务团队的现有服务。非客户问题不会把校招生当成摇摆户；仅从事实、业务参与和风险边界分析，专业能力仍有限。

可选：并行会诊、顺序链式（摇摆户→营销→风控）、需求先行双路并行、风控先行双路并行、交叉质疑一轮反馈。最后一种会实际新增三队互读、质疑更新及独立复审。默认自动选择可用 LLM 或规则；规则按敏感权限关键词优先风控、营销客户问题优先需求、其他并行，不代表最优策略。训练路由器明确标为未接入。

## 论文方法与实现边界

[MasRouter ACL 2025](https://aclanthology.org/2025.acl-long.757/) 采用训练后的级联控制器选择协作、角色与模型；当前是受固定名册约束的工程适配，只有一个模型候选，不是原版训练控制器或多模型择优。官方控制器训练包含任务监督与基于效用的策略梯度，不意味着必须训练基础大模型。跨场景需统一能力描述、收集效果及成本反馈，并按未见场景检验泛化。仅单次选择也可比较监督学习或上下文 bandit；多步动态恢复再考虑序列强化学习。不能用模型自评通过率代替业务成效。

[MAS-Resilience ICML 2025](https://proceedings.mlr.press/v267/huang25ay.html) 启发负责人质疑及独立 Inspector。一般细节、重复、补充数据建议只提示；严重错误须有类别、严重程度和原文引用才触发修订，最多两次修订、三次审查。未修好或审查结构持续无效的团队原文被隔离，下游只收到缺失说明。最终仍有实质问题则待人工复核，无最终放行；已通过团队结果保留。模型审查仍可能误判，未复现论文故障注入基准，也不保证事实正确。

## 可观测性与网络

单任务最多48次真实请求，通常手动/规则14次，LLM路由15次；交叉质疑手动通常20次，结构纠正和修订额外计数。普通输出最多3000 token、最终5000；同时最多两次请求，总体超时180秒。格式异常最多一次可见纠正，不自动重试网络失败。单个子任务失败时，仅将缺失说明与成功材料交给负责人；团队分支失败时隔离该团队，保留其余结果，全部团队不可用则停止。API面板显示真实HTTP状态、响应ID、模型、用量、耗时、时间及网络路径；历史成功不保证当前网络。停止会传递取消信号，已处理请求仍可能计费。

使用原生 HTTPS 请求与全局代理，避免 fetch 的短连接建立超时。自动模式依次考虑 LLM_PROXY_URL、代理环境变量、已启用 Windows 系统代理；没有显式代理走系统网络，适配 VPN TUN。TLS校验保持开启，无自动切换路线。可在 .env 指定 LLM_NETWORK_MODE=proxy 和 LLM_PROXY_URL=http://127.0.0.1:实际端口；HTTP(S)代理需要 Node24.14+，不支持SOCKS/PAC。

运行历史保存在 Git忽略的 data/hierarchy-v2/state.json。旧失败和旧角色保留原样并显示历史版本提示，不伪造改写。服务仅监听本机、校验同源。当前没有外部检索、银行数据或真实生产操作权限。

`node --test` 执行离线回归，不产生API费用，覆盖五种模式、固定名册、严重/一般意见分级、结构纠正、隔离交接、取消、并发限制、API适配和代理。真实回放记录位于本机 data/fixed-teams-replay.json 与 data/fixed-teams-final-validation.json，不上传Git。
