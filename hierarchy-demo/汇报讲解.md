# 分层多智能体协作 Demo：讲解与汇报稿

依据当前 fixed-teams-v4 源码核对。入口：http://127.0.0.1:4323/ 。本文介绍当前入口，不将旧原型能力算入新版。

## 1. 项目定位

这是一个由两篇论文启发、真实调用 DeepSeek 的分层多智能体协作原型。它验证：如何约束已有 Agent 的职责、选择协作结构、控制消息交接，以及在发生错误时修订、隔离并保留可用结果。

它目前属于“协作编排与可靠性交互层”。业务专家 Agent 的知识、工具、数据和专业效果由业务侧另行建设；本项目当前通过不同职责提示模拟这些接口，尚未连接你们已有平台上的三个实际 Agent 服务。

当前不能宣称：完整复现两篇论文的实验成绩、已训练 MasRouter 业务路由器、具备银行生产操作能力、已经实现自进化、已经证明多 Agent 优于单 Agent。

## 2. 一次任务如何运行

用户输入问题 → 后端创建运行记录 → 手动/规则/LLM 确定协作图 → 运行六个子角色分析 → 三位顶层负责人分别汇总和质疑 → 每条团队结论独立审查 → 按依赖交接 → 可选交叉质疑轮 → 综合答案 → 最终独立审查 → 交付或保留结果等待复核。

这是逻辑流程。并行模式下不同团队可以交错执行，并非所有子角色都结束后才启动所有负责人；实际 API 请求最多同时两个。

以“校招生没有深入参与信用卡业务”为例：先接受这是用户报告的现象；各团队从事实、业务参与、权限边界三个角度分析。缺少本行数据时不能断言具体制度有问题，但可以给出明确标为假设的成因、条件建议和核验项。

## 3. 页面模块逐一解释

| 页面模块 | 做什么 | 意义与技术 |
|---|---|---|
| 顶部架构图 | 展示路由、三个团队、质疑与审查 | 帮助理解系统分工；这是概念示意，不是训练完成证明 |
| API 调用证据 | 展示 HTTP 状态、提供方响应 ID、返回模型、时间、usage、耗时、网络路径 | 证据来自真实 API 响应；页面默认展示最近成功记录，可能来自另一任务，具体任务须点其调用记录 |
| 验证 API 连接 | 显式发起一次小请求 | 验证当前连接，会产生 API 用量；已配置密钥不代表连接成功，历史成功不保证现在成功 |
| 指标卡片 | 调用记录数、返回 token、实际协作方式、已放行消息版本数 | 观察运行成本和进度。调用记录含排队/失败项，不等于每项都计费；token 为提供方已返回的 usage；4 条放行通常是3队+最终，并非4个业务Agent |
| 协作方式选择 | 自动或手动选五种结构 | 便于理解与对照同一问题的不同协作方式；当前每种结构均有真实执行路径 |
| 自动路由器选择 | LLM 或规则基线，训练路由器禁用 | 区分选路机制与执行能力：规则不付选路推理费，后续执行仍调用 DeepSeek |
| 问题输入与运行 | 自由输入1—4000字符的问题，创建任务 | 后端校验输入并返回任务ID，任务在后台持续执行；关闭网页不会自动取消 |
| 停止执行 | 取消在途请求，后续排队请求发送前检查取消状态 | 用 AbortController/AbortSignal；提供方已处理的请求仍可能计费，不承诺退款 |
| 运行历史 | 查看最近任务与原始状态 | 当前保留最近20个任务；旧角色和旧失败不会被新版规则改写 |
| 实际协作拓扑 | 展示本任务团队、子角色、依赖、负责人和Inspector | 由运行数据动态渲染，不是预录动画。并行波次不等于任意两队自动共享全部上下文 |
| 事件与消息轨迹 | 记录排队、调用、隔离、修订、放行、结束等 | 用时间戳与序号解释“发生了什么”，可定位网络、格式、内容三类不同问题 |
| 详情面板 | 查看真实输入、输出、提示词、用量和审查版本 | 支持复盘模型为何得出结论；记录的是发送和返回正文，不是模型隐藏思维链 |
| 导出运行JSON | 下载当前任务结构化记录 | 用于复盘与后续实验分析；包含问题和模型正文，分享前应检查业务信息 |
| 问题答案与审查结果 | 呈现摘要、行动建议、假设、限制、警告 | 避免把条件分析当已核实事实；若最终审查未通过则保留阶段结果，不显示已批准答案 |
| 论文页 | 对比原论文和当前实现，说明团队、训练与自进化边界 | 提供研究依据，也防止把工程适配说成论文完整复现 |
| 源码页 | 只读查看列入白名单的后台源码 | 便于证明编排、审查、代理适配的具体实现；不提供任意文件或密钥读取 |

## 4. Agent 到底是什么

当前 Agent 是“职责提示+当前任务上下文+一次或多次模型调用+应用保存的运行状态”。不同 Agent 共用同一 DeepSeek 模型；没有为每个角色单独训练权重，也没有分别启动九个独立服务。

| 顶层团队 | 两个固定子角色 | 负责人职责 |
|---|---|---|
| 摇摆户 Agent | 需求与事实核查；行为与障碍分析 | 整理事实、需求、障碍和假设；非客户题目不能把内部人员当摇摆户 |
| 营销 Agent | 方案设计；效果评估 | 综合业务方案、实施前提和验证指标；不宣称已执行建议 |
| 风控 Agent | 权限与边界；证据与承诺检查 | 检查授权、事实混淆和无依据承诺；不知道本行制度时明确待核实 |

这些子角色是当前演示名册，不能对外说成已接入团队实际子 Agent。模型不能创造注册表外的顶层身份。三队目前始终参与，尚未实现按能力只激活一部分团队，因此处理不匹配场景会有额外开销和专业局限。

负责人是同一模型的额外一次调用，读取本队子结果及允许的上游材料，检查冲突、汇总有用结论。子输出先进入负责人上下文，没有逐条单独经过 Inspector；Inspector 的主要交接关卡在团队输出和最终答案。

## 5. 规划、分工、路由和调度的区别

- 规划：确定协作方式和各团队针对本题的工作。
- 分工：模型可给现有顶层团队分配本题任务；六个子角色的基本职责固定，尚不是自由拆分成任意数量的新任务。
- 路由：主要决定执行顺序与谁能读取谁的已审查消息。当前模型池只有一个模型，因此没有真正的多模型择优。
- 调度：程序检查依赖是否完成，决定启动哪个节点，控制并发、取消和预算。模型给计划，程序执行和校验。

规则：含“生产、敏感数据、隐私、授权、合规审批”优先风控先行；否则含“营销、摇摆户、客户”选需求先行；其余并行。它是人工关键词基线，没有训练和最优性保证。

LLM：将问题、固定团队名册、五种候选方式提交给 DeepSeek，要求返回 JSON 的方式、理由和任务。程序验证候选是否合法、是否出现非法角色。结构不合法最多再发一次显式纠正请求；仍无效则记录警告并显式用固定并行基线。网络失败不属于该结构回退，不会偷偷伪造计划。

## 6. 五种协作结构

| 结构 | 消息关系 | 适用考虑，而非已证明最优 |
|---|---|---|
| 并行会诊 | 三队不读彼此首轮结论，最后综合 | 独立视角、减少前序锚定；可能出现分歧 |
| 顺序链式 | 摇摆户→营销→风控，风控能看前两队 | 需求到方案到风险逐步细化；前序错误可能影响后续，耗时较长 |
| 需求先行 | 摇摆户→营销、风控 | 先统一需求，后两队独立工作；本模式下营销不会自动读取风控同期结论 |
| 风控先行 | 风控→摇摆户、营销 | 先明确权限约束；风控首轮也可能遗漏后续方案才出现的风险 |
| 交叉质疑 | 三队独立初稿→各队逐轮读取上一轮已审查快照→更新→再审查→综合 | 用额外调用检查分歧；支持1—3轮，每轮统一读取上轮审查快照；不是无限辩论 |

## 7. Challenger、Inspector 和错误恢复

Challenger 是负责人对材料提出有依据的质疑；交叉质疑模式还读取其他团队初稿。Inspector 是使用专门审查提示、单独上下文发起的另一请求。它与执行者共用基础模型，因此“独立”指调用与职责分开，不代表错误统计独立或外部事实权威。

程序将审查意见分两类：

- 一般建议：重复、细节不够、可补数据等，允许带警告交付。
- 实质问题：未知当事实、明确矛盾、虚称已实施、越权操作建议、完全未回答题目。必须有认可的类别、major/critical严重程度，以及能在候选正文中找到的逐字引用，才要求修订。

引用匹配只是检查意见能否定位，不能证明审查一定正确。程序只验证部分字段，JSON模式也不能保证语义正确。

恢复过程：记录候选版本→发现实质问题→隔离原版本→把问题反馈原角色→生成修订→独立复审。最多两次修订，即最多三次审查；仍失败则只交接缺失说明。最终答案仍有实质问题时状态为待复核。

网络故障、格式故障、内容故障分别处理：网络不自动重试；格式最多一次可见纠正；内容按上述版本回路处理。首轮团队阶段的单个子任务失败可用其余材料继续，整个团队失败则隔离分支，全部团队无可用结论就停止。交叉质疑额外轮或最终综合/审查发生请求故障，当前仍可能结束整项任务并保留已接受的团队材料，并非所有阶段都有断点续跑。

隔离是应用选择不把该原文交给下游，不是操作系统沙箱；成功消息也可能有错误。风控业务角色与 Inspector 不同：前者产出风险分析，后者检查任意团队消息能否交接。

## 8. 技术实现与后台模块

| 文件/技术 | 职责 | 意义 |
|---|---|---|
| console.html / console.css | HTML、CSS界面 | 不依赖前端框架，展示控制台、图与论文对照 |
| console.mjs | 浏览器原生JavaScript、fetch、DOM渲染 | 约1.5秒轮询状态接口并更新页面；不是WebSocket/SSE实时流，答案按完整响应返回 |
| server.mjs | Node.js原生HTTP服务器 | 静态页面、启动/取消、配置重读、历史持久化、源码白名单；一次一个任务 |
| paper-runtime.mjs | 自定义异步编排和状态机 | 注册表、五种依赖图、Promise.allSettled、并发名额、审查版本、隔离和恢复；未使用LangGraph或AutoGen |
| model-provider.mjs | DeepSeek Chat Completions适配 | 提示组装、JSON输出、正文/usage解析、完整结束检查、超时和证据记录；当前thinking关闭、非流式 |
| model-transport.mjs | Node原生HTTPS | 发送请求、接收完整正文、取消、响应大小限制；不自动重试，TLS验证开启 |
| model-network.mjs | 代理解析和Node全局代理 | 环境代理、已启用Windows代理或系统网络/VPN TUN；不替用户切换VPN |
| data/hierarchy-v2/state.json | 本地JSON持久化 | 保存运行、事件、调用与版本；串行写临时文件再替换，减少写入竞争；当前没有数据库 |
| *.test.mjs + node --test | Node自带测试框架、模拟模型返回 | 验证状态推进、固定身份、结构、隔离、取消、代理等；离线测试不证明真实模型业务效果 |

后端主要接口：GET /api/state 返回运行状态；POST /api/start 启动任务；POST /api/cancel 停止；POST /api/reload 重读配置；POST /api/probe 验证连接；GET /api/source 读白名单源码。旧 evolve/activate/rollback 接口保留，但新 paper-live 任务不接入旧演化流程。

本地启动命令：node hierarchy-demo/server.mjs。Node24.14+支持当前HTTP(S)全局代理功能。服务地址4323属于本地地址，GitHub保存源码不等于部署在线后台。

## 9. 调用成本与可观测证据

无修订、无格式纠正时，手动/规则普通模式14次：6子角色+3负责人+3团队Inspector+1综合+1最终Inspector。LLM自动再加1次选路，通常15次。每轮辩论增加3次更新+3次审查；默认两轮手动26次，LLM自动27次。

结构纠正与内容修订会额外计数。单任务预算上限48条请求记录；普通输出上限3000 token、最终5000；单请求总体超时180秒。上限不是固定消费额，token不是人民币费用。未收到usage的故障请求费用可能未知。

已保存的本地校招生题目回放：任务55a35914-4bda-4c0b-b7c4-c92dfb4b2902，LLM选parallel，19次调用，API返回总计38499 token，含审查建议交付。此前也有真实网络失败记录，保留不改。66项离线回归在上一轮修改后通过；不等于66道真实业务题评测，也不等于业务成功率。

## 10. 两篇论文分别提供什么

[MasRouter（ACL 2025）](https://aclanthology.org/2025.acl-long.757/)研究级联控制器如何联合选择协作模式、角色与LLM，兼顾效果和成本。本demo采用其分阶段路由的组织思路，但固定三队、单模型，当前选路由规则或LLM完成，没有部署训练后的原版控制器。

[MAS-Resilience（ICML 2025）](https://proceedings.mlr.press/v267/huang25ay.html)研究错误Agent的传播影响，并引入Challenger与Inspector。本demo借鉴质疑与消息审查；严重程度规则、预算、两次修订、部分故障降级等是当前工程设计，不能逐项说成论文原样算法。没有复现其故障注入实验和恢复率。

当前依赖图也不是把论文所有结构逐个原样移植。例如双路并行本身没有两个分支之间的双向反馈；不能仅因看起来像层次结构，就声称具备论文测试出的同等韧性。

## 11. 强化学习、多场景与自进化

未来可训练较小的路由控制器，不必训练基础DeepSeek。先收集统一格式的任务、团队能力、约束、选图、产出、业务评分、用量与耗时，才能比较路由策略。不同结构的对照结果需要额外真实执行和评估成本，不会凭日志自动出现。

单次选图可比较监督学习、上下文bandit及LLM基线；若执行过程中反复选择下一个团队、修订次数和停止时机，更接近序列强化学习。效果奖励不能只用模型自评通过率，需业务核验及成本惩罚。多场景应按整类场景留出评测，检查新任务和新能力组合；失败或超出分布应有明确回退。

本次恢复只更新本任务消息，不更新下次路由权重、提示、长期记忆。要称自进化，需提出策略/提示/记忆候选，独立对照验证、版本发布、持续监测及回滚；当前尚未形成此闭环。

## 12. 当前价值与下一步验收

当前可以证明流程能真实运行、依赖交接可以审查、失败能够定位、部分分支故障可隔离、用量可记录。尚不能证明质量优于单模型、成本更低、事实可靠或跨场景泛化。

建议下一步优先接真实Agent接口和能力描述，再用同一批代表性任务比较单Agent直答、固定结构、LLM路由和规则路由。由业务人员盲评正确性、可执行性和权限问题，同时记录token、耗时、失败率、误阻断率、错误漏放率。训练路由器在这些基线之上增加，才能判断收益。

## 13. 可直接口述的三分钟稿

我们目前搭建的是一个论文启发的分层多智能体协作原型，主要负责已有Agent如何分工、传递材料和处理错误。

系统按摇摆户、营销、风控固定三个顶层团队，每队两个演示子角色。现在以不同职责提示真实调用同一个DeepSeek模型，尚未连接团队已有Agent的知识和工具。输入问题后，可以手选五种结构，也可以让受约束的大模型或规则基线选路。程序根据依赖执行，避免模型擅自创建新身份。

我们参考MasRouter把协作方式、角色和模型选择分阶段考虑，但目前没有使用训练后的原版控制器，也只有一个模型候选。参考MAS-Resilience加入负责人质疑和单独Inspector审查：一般意见保留提示，实质问题修订复审，仍未修好则隔离原文，尽量避免错误继续传递。

看板显示真实API响应、输入输出、消息版本和用量。当前已跑通校招生问题，最新记录19次调用、38499 token，含审查建议完成；离线状态机等回归66项通过。这个结果证明流程跑通，不代表业务正确率已经验证。

下一步重点是接真实业务Agent，并与单Agent和不同协作结构做同题对照。待有可靠的效果与成本数据后，再比较训练路由器和LLM路由；跨任务自进化还需要独立验证、发布和回滚闭环。


## 2026-10-22 多轮辩论更新

此前仅有一轮互读，现已支持1—3轮，界面默认2轮；初稿不算辩论轮。每轮三个顶层团队读取同一份上轮已审查快照，回应质疑、更新完整结论，再由Inspector检查。轮内并发调度，API请求仍最多两个；整轮完成后才进入下一轮。每轮保存前后快照、分支状态、调用与消息版本，可在图下点击逐轮记录查看。

新候选不可交接或请求失败则保留该队上轮已审查结果，并显示警告；取消立即终止。单任务仍48次请求预算，开始一轮前至少预留本轮6次及最终综合审查2次，修订可能耗尽预算并使任务停止。没有以模型自评自动认定收敛，保留不同意见，不强求共识。

无修订时手动辩论为14+6×轮数次调用：1轮20次、2轮26次、3轮32次；LLM选路另加1次。多轮不等于跨任务学习或强化学习，也不保证答案更正确。此前文档中的一轮调用数和限制描述以此更新为准。


## 自动结束辩论（当前默认）

默认debateMode=auto，用户不需要指定轮数。每轮团队消息审查完成后，新增一次进展评估请求，比较前后结论、回应、实质修改、未回答质疑与未解决问题；问题必须有本轮原文定位，并标出能否在当前材料下解决。可解决问题会送入下一轮focus。

程序检查评估结构、原文定位、未解决问题与停止结论是否冲突；完全相同的答案或连续两轮评估无实质修改会停止，模型声称稳定但仍有可处理问题时继续。模型评估仍会误判，原文定位不能证明事实正确，也不是语义收敛的数学证明。

停止原因区分：方案稳定、无进展、需要外部信息、材料不完整、轮数上限、预算限制、评估不可用。停止不代表共识或正确性；最终综合接收停止原因和各轮评估，仍需最终Inspector。自动模式最多3轮、总请求预算48；无修订时手动起步14次，每轮通常增加6次辩论审查和1次评估，即14+7×实际轮数，LLM选路另加1次。结构纠正与修订另计。

固定1—3轮保留在高级设置（debateMode=fixed），用于对照实验，不调用进展评估。旧任务历史保留原结束方式。评估请求失败时不自动重试，停止追加讨论并用已审查材料进行带限制综合；最终调用也可能失败。此前默认固定两轮的描述由本节替代。
